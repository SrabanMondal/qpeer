# QPeer Build Progress Notes

## Device test procedure: QR join with one phone (owner's instruction, 2026-10-15)
There is only one test phone, so it plays both roles:
1. **Business side:** switch the app to Business mode, open the queue → **Show QR code**, take a screenshot with `adb exec-out screencap -p`, crop/save it on the laptop (e.g. `G:\dev\qpeer\.orch\qr\<queue>.png`), and open it full-screen on the laptop display.
2. Before joining, make sure the walk-in GPS check can pass: phone location **on**, and the business pin within the join radius of where the phone is (Set pin → **Use my location**, or temporarily raise the queue's join radius).
3. **Customer side:** switch the app back to Customer mode (normal user profile).
4. **Ask the owner** to scan the QR on the laptop screen with the phone (in-app scanner, and also the phone camera to test the deep link), then continue checking the ticket screen with adb screenshots.
5. Drive the console (Next / No-show / Pause) through the API or by switching back to Business mode, and check the ticket updates live.

Exact taps for the Step 2 screens (one phone):
- **Open the queue first:** Business mode → **Queue** tab (console) → pick the queue in the "Queue" chips if there are several → **Open queue**. The banner turns teal "Open — service active" with "Walk-in check: GPS · <radius> m" and a "Live" badge.
- **QR:** Business tab → business → queue → **Show QR code** → screenshot as above.
- **Join:** Profile → switch to Customer → Home → **Scan QR to join** (route `/scan`) → point at the laptop screen → join screen (`/q/<id>`) → **Join queue** → allow location → "Get alerts for your turn?" → **Allow alerts** → system prompt → ticket (`/token/<id>`). Phone-camera path: open the camera app, point at the QR, tap the `qpeer://q/…` suggestion → the same join screen.
- **Already joined:** joining again opens the existing ticket. The Queue tab (Customer) lists it under **Active**.
- **Console back:** Profile → Business → Queue tab → **NEXT** (ticket turns green "It's your turn"), **UNDO** within 30 s, **No-show** on the Called row (ticket shows the grace countdown; console lists it under "Late — grace"), **Admit**, **Served**, **Pause/Resume**, **Close for the day**. One phone cannot show the console and the ticket at once: after each console action, switch to Customer → Queue tab → tap the ticket (it refetches on open), or leave the ticket on screen and drive the console through the API to watch live updates.
- adb deep link without a QR: `adb shell am start -a android.intent.action.VIEW -d "qpeer://q/<queueId>"`.

## Step 1 backend — business module (2026-10-15, branch `feat/step1-backend`)
- **Layout** now follows architecture doc §3: `src/env.ts`, `middleware/{request-context,auth,guards}.ts`, `lib/{errors,validate,time,ids,geo}.ts`, `db/{schema,client}.ts`, `modules/{identity,business,dev}/`. `src/auth.ts` moved into `middleware/auth.ts` (`makeFirebaseVerifier` still exported). `queue-do.ts` untouched (Step 2).
- **Errors**: `AppError(status, code, message?, details?)` + `onError`; body `{ error, message?, requestId, details? }`; unknown routes → 404 `not_found`; validation → 400 `invalid_input` with `details: [{ path, message }]`.
- **Guards**: `requireRegistered()` (403 `registration_required`), `requireBusinessRole(role, "business" | "queue")` → 404 when the business/queue is missing **or** the caller isn't a member, 403 `forbidden` for staff on owner routes.
- **Endpoints**: `PATCH /v1/me`, `POST /v1/businesses`, `GET /v1/me/businesses`, `GET/PATCH /v1/businesses/:id`, `POST /v1/businesses/:id/{deactivate,activate,queues}`, `GET/PATCH /v1/queues/:id`, `POST /v1/queues/:id/archive`.
- **Data**: migration `0001_step1_business.sql` adds `businesses`, `business_members`, `queues`, `users.free_lane_blocked_until`, and converts `users` timestamps seconds → ms (hand-added `UPDATE … * 1000` guarded by `< 1e11`). All timestamps are `integer(mode: "timestamp_ms")`.
- **Shared**: `BusinessCategory`, `LatLng` (now a zod schema; the type is unchanged), `HoursRange`/`WeeklyHours`/`defaultWeeklyHours()`, `QueueSettings` (+ `QueueSettingsPatch`, defaults per §8), request bodies, `BusinessView`, `QueueView`, `MyBusinessesResponse`, `QueueInfoResponse`, `ErrorCode`, `ValidationIssue`; `ErrorResponse.error` is now the `ErrorCode` enum.
- **Decisions**:
  - The token `name` claim only fills `display_name` while it is empty, so a name set with `PATCH /me` survives later sign-ins (previously every request overwrote it).
  - Request bodies are `.strict()` (unknown keys → 400). Update bodies need at least one field. `phone: null` clears the phone. The pin can be moved but not removed.
  - Owner routes also run `requireRegistered()` first (defence in depth).
  - Queue limit (10 active) is enforced in one `INSERT … SELECT … WHERE count < 10` so parallel creates can't exceed it.
  - `settings_version` only increments when the merged settings actually differ; queue updates are guarded on the version read (409 `conflict` on a concurrent change).
  - Archived queues: can't be edited (409 `invalid_state`), archive is idempotent, no unarchive yet. Members see archived queues; public views don't.
  - Deactivate/activate are idempotent; `updated_at` only moves on a real status change.
  - `GET /v1/queues/:id` returns `{ queue, business, myRole }`; 404 for non-members unless the queue is active and the business is listed.
  - Lists are ordered oldest first and not paginated yet (a user has few businesses; max 10 active queues each).
- **Deferred**: deactivation closing open queues, pushing new settings to QueueDO, `countActiveTokens` (returns 0, `// Step 2: ask QueueDO`), staff invites (BIZ-17), pagination of `/me/businesses`, `requireDevEnv` beyond "not demo".

## Step 2 backend — live queue engine (2026-10-15, branch `feat/step2-backend`)
- **QueueDO** (`src/queue/`): `queue-do.ts` (RPC, WebSocket, alarm), `storage.ts` (DO SQLite schema v1 in `meta.schema_version`; the Step 0 stub `meta` is dropped on upgrade), `ordering.ts` (sort keys, skip), `eta.ts`, `scheduler.ts` (single alarm, IST hours, backoff), `outbox.ts` (D1 applies), `protocol.ts` (socket tags, alert bits/texts). Every mutating RPC runs its state change in one `transactionSync`, then broadcasts, reschedules the alarm and drains the outbox (drains are chained, never overlap). RPCs return `DoResult` values (`{ ok, value } | { ok: false, code, message, details }`); the Worker maps codes with `unwrap()`.
- **RPC**: `init`, `updateSettings`, `setLabels`, `open`, `close` (returns paid tokens), `pause`, `resume`, `checkJoin`, `checkQuota`, `allocate` (idempotent by `paymentOrderId`), `insertTriage`, `next(counter)` (auto-serves the counter's CALLED token), `undoNext` (30 s), `skip`, `noShow`, `admit`, `served`, `leave`, `cancel`, `getToken`, `getState`, `getSummary`, `countActiveTokens`, `ping`, `fetch` (WebSocket), plus test helpers `testAdvanceClock` (only when `ENVIRONMENT=local`) and `pendingOutbox`.
- **ETA** math in `packages/shared/src/eta.ts` (EWMA α 0.3 + EW variance, 5× median cap over 50, cold start < 3 intervals with σ = 50% of the hint, range ±max(1.28σ√k, 1 min, 10% of k·mean), be-back-by −5 min, `leaveHomeBy()` for the app). Interval = now − max(lastCall, head's join time) − paused time.
- **Outbox → D1**: `token_upsert` (rev-guarded), `snapshot` (lat/lng copied from `businesses` at write; ≤ 30 s throttle, open/close/pause flush at once), `analytics` (IST hour rows flushed at hour end and on close; dedupe via `outbox_receipts`), `strike`, `push`. Backoff 5 s/30 s/2 min/10 min/30 min.
- **Alerts**: `head_back` (expected call ≤ 15 min away, not in the first 10 min after joining, not for the head), `next` (on reaching the head; not when joining at the head), `called` (counter in text), `grace_started`, `queue_paused`, `queue_closed`; bit set before enqueueing. Expo transport is injectable (`pushOverride` in `modules/notifications/expo-push.ts`); tickets → `push_tickets`; `DeviceNotRegistered` tickets/receipts delete the device.
- **Live**: Hibernation sockets tagged `t:<tokenId>` / `console`; heartbeat via auto-response; tokens within 20 positions get every change, others ≤ every 30 s (alarm-driven).
- **Worker**: `modules/queue/{routes,service,do-client}.ts`, `modules/notifications/{routes,service,expo-push}.ts`, `cron/jobs.ts` (hourly receipts; 15-min list empty). Business follow-ups: create → `init`, settings/rename → `updateSettings`/`setLabels`, archive uses `countActiveTokens` and closes the session, deactivate closes all queues (BIZ-08), pin move updates `queue_snapshots`, business views carry `queues[].live` from snapshots, `GET /queues/:id` carries `live` from the DO.
- **D1**: migration `0003_step2_queue.sql` (queue_snapshots, tokens, devices, push_tickets, free_lane_strikes, analytics_hourly, outbox_receipts).
- **Decisions** (also in architecture §23): WebSocket auth = `Authorization` header on the upgrade; endpoint rate limits deferred (`TODO(NFR-11)`); skip = behind next 3 or end; client ping/pong auto-response; console socket gets full `ConsoleState`; staff may join their own queue; free-lane block 7 days after the 3rd no-show in 30 days; pause blocks walk-in joins and Next (paid allocation and triage still allowed); paid cap per user → `quota_full`; Next with nobody waiting but someone CALLED just serves them.
- **Tests**: `test/queue-do.test.ts` (DO RPC, alarms, outbox incl. D1 outage, restart, WebSocket fan-out, alerts) and `test/queue-api.test.ts` (join rejections in order, location never stored/logged, tokens, console, IDOR, live route, devices, cron, BIZ-08/11/12, snapshots). `npm run check` green (API 100 tests, shared 56).
