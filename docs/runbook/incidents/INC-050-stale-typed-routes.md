# INC-050: A new route failed the typecheck until `expo start` ran

| Field | Value |
|---|---|
| Date found | 2026-10-16 |
| Severity | S4 |
| Area | tooling |
| Status | fixed |
| Original ID | none (fix batch) |

## Summary

The new screen `queue/[id]/verify` made `tsc` fail in the console with "Type '/queue/[id]/verify' is not assignable". Expo Router's typed routes live in the gitignored `.expo/types/router.d.ts`, which only `expo start` writes; `expo export` does not. The console now opens the route with a plain string.

## Impact

None for users. Without the change, `npm run check` would fail on every checkout until someone runs Metro.

## Detection

`npx tsc --noEmit` in `apps/mobile` during the fix batch.

## Timeline

Unknown.

## Root cause

Typed routes are generated by the dev server only. A fresh worktree also has no `expo-env.d.ts` and no `.expo/types` (both gitignored); they were copied from the main checkout to run the check.

## Fix

Branch `feat/fix-batch-rebuild`, commit 75c38f1: `router.push(\`/queue/${id}/verify\` as Href)` with a comment.

## Verification

`npm run check` passes with the old `router.d.ts`.

## Follow-ups

None.

## Lessons

Link to a route added in the same change with a string `Href`, or run `expo start` once before the typecheck. A fresh worktree needs `apps/mobile/expo-env.d.ts` and `.expo/types` before `npm run check`.
